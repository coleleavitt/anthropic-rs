## Merge resolution decisions affecting wire behavior

These calls were made while resolving the merge. Where they differ from either side's commits below, **they are the final behavior**.

1. **cch / billing header (`cch.ts`)**
   - Upstream canonical signing wins over the fork's literal `cch=00000;` (the 2.1.260 claim).
   - Signing algorithm:
     1. Parse the serialized body.
     2. Set `model = ""` and delete `max_tokens`.
     3. Re-serialize with `JSON.stringify`.
     4. Take xxHash64 with seed `0x4d659218e32a3268`, keep the low 20 bits (`& 0xfffff`), and format as 5 hex digits zero-padded.
     5. Replace the `cch=00000;` placeholder in the first `system` block's `x-anthropic-billing-header` text.
   - The signer only fires when the body matches this regex (the header must be `system[0]`):

     ```
     "system":[{"type":"text","text":"x-anthropic-billing-header: cc_version=[^;"]+; cc_entrypoint=[^;"]+; cch=XXXXX;
     ```
   - The fork's env switch `ANTHROPIC_AUTH_CCH_MODE` is kept:
     - `native` (default) = upstream signing
     - `literal` = the fork's 2.1.260 placeholder
     - `hmac` = HMAC-SHA256(key=`CCH_SALT`, body)[0:5]
     - `xxhash` = raw-body xxHash without canonicalization
   - Header text:

     ```
     x-anthropic-billing-header: cc_version=<ver>.<suffix>; cc_entrypoint=<ep>; cch=00000;[ cc_workload=<w>;][ cc_is_subagent=true;][ cc_prev_req=<id>;][ cc_prompt_id=<uuid>;]
     ```
   - Where each optional segment comes from:
     - `cc_workload` and `cc_is_subagent`: fork.
     - `cc_prev_req` and `cc_prompt_id`: upstream lineage.
   - Validation regexes (upstream):
     - request id: `/^req_[A-Za-z0-9_-]{8,128}$/`
     - prompt id: `/^[0-9a-f]{8}-[0-9a-f]{4}-[1-8][0-9a-f]{3}-[89ab][0-9a-f]{3}-[0-9a-f]{12}$/i`
   - Version suffix: `sha256(CCH_SALT + sampled + version).hex[0:3]`.
     - `CCH_SALT = '59cf53e54c78'`
     - `sampled` = the first-user-text chars at `CCH_POSITIONS = [4, 7, 20]`, with `'0'` for any missing char.
   - First-user-text source: the pinned per-session value (`ClaudeCodeFirstUserTextTracker`, LRU of 1000). If not pinned:
     1. Take the first `role:user` message, skipping `isMeta:true` messages (fork addition).
     2. A string content is used as-is.
     3. Otherwise, a text block containing `<command-name>` is sliced from that tag.
     4. Otherwise, the last non-empty text block is used.
   - Default `version` = the fork's live npm-tracked version (`getCachedClaudeCodeVersion()`) instead of the pinned constant.
   - `stripBillingLineageFields` / `stripBillingLineageFromBody` (upstream) remove `cc_prev_req` / `cc_prompt_id` before a body is reused (cachekeep warm, relay replay).

2. **Betas (`claude-code.ts`)**
   - Upstream tuples win over the fork's restructured `BASE ⊂ FULL` tuples.
   - Full-agent tuple, used when the body has non-empty `tools`, `system`, `thinking`, `context_management`, `output_config` and `diagnostics`, in this order:

     ```
     oauth-2025-04-20, interleaved-thinking-2025-05-14, thinking-token-count-2026-05-13, context-management-2025-06-27,
     prompt-caching-scope-2026-01-05, claude-code-20250219, advisor-tool-2026-03-01, advanced-tool-use-2025-11-20,
     mid-conversation-system-2026-04-07, effort-2025-11-24, fallback-credit-2026-06-01, extended-cache-ttl-2025-04-11,
     cache-diagnosis-2026-04-07
     ```
   - `redact-thinking-2026-02-12` is deliberately omitted.
   - Structured-output tuple (`output_config.format.type == json_schema`):

     ```
     oauth, interleaved-thinking, thinking-token-count, context-management, prompt-caching-scope, advisor-tool-2026-03-01,
     structured-outputs-2025-12-15, cache-diagnosis
     ```
   - Base tuple: oauth, interleaved-thinking, thinking-token-count, context-management, prompt-caching-scope, advisor-tool, advanced-tool-use, extended-cache-ttl, cache-diagnosis.
     - **No `claude-code-20250219`** in base.
   - Appended to any tuple, in this order, then deduped:
     1. `fast-mode-2026-02-01` if `speed:"fast"`.
     2. **[fork re-applied]** `effort-2025-11-24` whenever `output_config.effort` is set.
     3. **[fork]** `context-1m-2025-08-07` for 1M-capable models (a `[1m]` marker or a prefix list) unless `suppressContext1m`.
     4. Caller extras.
   - Fork headers kept on top of upstream `applyClaudeCodeHeaders`:
     - `user-agent: claude-cli/<liveVer> (external, <CLAUDE_CODE_ENTRYPOINT|cli>[, agent-sdk/<v>][, client-app/<app>])`
     - `x-stainless-helper-method: stream` when `body.stream === true`
     - Env-forwarded, percent-encoded outside printable ASCII:
       - `x-claude-remote-container-id` ← `CLAUDE_CODE_CONTAINER_ID`
       - `x-claude-remote-session-id` ← `CLAUDE_CODE_REMOTE_SESSION_ID`
       - `x-client-app` ← `CLAUDE_AGENT_SDK_CLIENT_APP`
     - `x-anthropic-additional-protection: true` when the `CLAUDE_CODE_ADDITIONAL_PROTECTION` env var is truthy
     - Per-request options: `x-claude-code-agent-id`, `x-claude-code-parent-agent-id`, `x-claude-code-request-class`, `x-claude-code-prev-tool-durations`

3. **Identity (`claude-code.ts`)**
   - Upstream: `resolveClaudeCodeIdentity(accessToken, model, accountIdentity, deviceIdentityOptions?)`.
     - The identity cache is keyed on the stable account identity: `identity:<id>`, `account:<uuid>:<id>`, and `compat:<token>` when there is no identity.
     - Bootstrap uuid lookups are keyed `<cacheKey>:<token>`.
     - `ProviderAccountUuid` is a branded type.
     - `getClaudeCodeIdentityForVerifiedAccount` skips bootstrap for custodian-verified accounts.
   - Fork on top, as adjusted after the merge: the persistent installation secret (32-byte hex in `~/.anthropic-accounts/device.json`) is loaded once. It no longer replaces every identity's `deviceId` directly, because that broke upstream's rule that distinct account identities never share a device id. Each identity's `deviceId` is `sha256_hex(installationSecret + "\0" + cacheKey)`, with the cache key being `identity:<accountIdentity>` or `compat:<token>`. The result is stable across restarts and distinct per account. It goes in `metadata.user_id`.
   - The bootstrap fetch `user-agent` is `claude-code/<liveVer>`.

4. **Models (`models.ts`, `fast.ts`)**
   - Upstream Opus 5.5 and Fable/Mythos 5.1 definitions win.
   - **`isClaudeOpus5Model` now EXCLUDES `claude-opus-5-5`**. Use `isClaudeOpus5FamilyModel` for shared behavior.
   - Fork helpers retained:
     - `canonicalClaudeModelId`
     - `modelSupportsAdaptiveThinking`, `modelSupportsMaxEffort`, `modelSupportsXhighEffort`
     - `clampEffortForModel`, `resolveThinkingShape`, `modelAllowsForcedManualThinking`
     - `modelRejectsDisabledThinking` (Fable/Mythos family + Opus 5.5)
     - `resolveClaudeFableMythos5Pricing`
     - The refusal route maps, which are category (e) and excluded from the port.
   - Fast mode: `isFastModeSupportedModel` = prefix `claude-opus-4-8` or `claude-opus-5` (which covers 5.5). Opus 4.6 and 4.7 are dropped.

5. **Accounts (`accounts.ts`, `network-errors.ts`)**
   - Upstream main prime lineage = the stable persisted `mainAccountId` (c52270c) wins.
     - The fork's refresh-fingerprint lineage handoff (`continueMainPrimeAuthLineageAfterRefresh`, `mainAuthLineagePreviousRefreshTokenFingerprint`) is removed.
     - The fork's `console.error` DEBUG prints are dropped.
   - Fork fallback-pool `logger.debug` admission/exclusion logging is kept on top of upstream's vault-served fallback logic.
   - Transient network codes = union of upstream and the fork's Claude Code `sie`/`gde` mirror:

     ```
     EAI_AGAIN ECONNREFUSED ECONNRESET EHOSTUNREACH ENETUNREACH ENOTFOUND ETIMEDOUT UND_ERR_CONNECT_TIMEOUT EPIPE
     ConnectionClosed ECONNABORTED ERR_SOCKET_CLOSED StreamSuspended ConnectionRefused ENETDOWN EHOSTDOWN
     FailedToOpenSocket ERR_PROXY_TUNNEL
     ```
     - Matching is on `error.code`, or on `"fetch failed"` or any listed code appearing as a substring of the message.

6. **Auth (`auth.ts`)**
   - Upstream: `isTransientNetworkError` comes from `network-errors.ts`, and `assertNotCustodyTombstone` runs before any refresh.
   - Fork kept: `abortableWait`, spend logging, `parseRetryAfterSeconds`, revoke, the refresh-token-expiry fields.

7. **Relay (`relay.ts`)**
   - Both sides kept: the fork's `AbortSignal` threading (positional, first) and upstream's `authorizeAttempt` / `RelayAuthorizationError` (second).

8. **Post-merge fixes with wire effect (all in the merge commit)**
   - A Claustrum custody tombstone in the host auth bypasses fork shared-store reconciliation, so it reaches upstream's custody gate unchanged. The code is in OpenCode `shared-auth.ts`. For a Rust port: never mirror a tombstone into the shared account store.
   - The Pi router's synthesized killswitch 429 (`retry-after: 60`) now also sends `x-should-retry: false`. Core `classifyRetry` honours `x-should-retry` before status, so a local policy block is not retried.
   - The fork's pre-send primary quota probe (`GET /api/oauth/usage`) is skipped when no fallback is configured, and under scoped custody. Upstream's custody poll bounds apply there.

9. **Constants**
   - `USER_AGENT = claude-cli/${CLAUDE_CODE_VERSION} (external, ${CLAUDE_CODE_ENTRYPOINT})` (upstream constant).
   - The live path uses the fork's `getClaudeCodeUserAgent()`.
   - `CLAUDE_CODE_VERSION = '2.1.280'` on both sides; `CLAUDE_CODE_BUILD_HASH` is kept but no longer used for the suffix.
   - Stainless: package `0.112.1`, runtime `v26.3.0`.
